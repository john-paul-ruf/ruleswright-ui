## Layout (mount order in `index.tsx`)
Header (`spatialLabel` chip + **Spatial caption** `model <model> · reach.default <n>` or "this pack declares no spatial model", S03) → combat-over banner (when over) → Event log beside a side column: Phase / Declare / Step → Trigger offers → **Combat board** (grid packs only, S02) → **Turn order** (S03) → Combatants → "Replay & records" (`RecordsPanel recordable`, so no Resume here).

- **Combat board + Reposition control** (`board.tsx`, design "Combat board", "Reposition control"): tokens at `state.combatants[id].position` in roster order from `live.sides`; distances from the active combatant via `distance(fight.runtime, a, b)` (CA-15; no reach judgement). Reposition mode mirrors the store precondition (phase `awaiting-declare`, `pending.length === 0`, `!over` — CX-D10) and applies `store.move(completeMap)`; otherwise `combat-move-unavailable` shows the design line.
- **Turn order panel + Initiative provenance** (`order.tsx`, DF-CX-1): `state.order` rows, active = `state.active`, `round R · turn T+1 of K`; initiative block from `initiativeOf(log)` (absent → "initiative event not in this log").
- **Controls** (`controls.tsx`): the declare rejection card is `ErrorCard{kind:'library', operation: rejection.type, name: payload.kind, cards:[{rule, jsonPath: resource, message}]}` → `declare:rejected · <kind>` / `<rule> <resource>` / message (design "Declare rejection examples"). `ActionDetail` under the Declare select shows `cost`/`tags`/`trigger.on`/`valid` verbatim (CX-D4, no affordability preview). `CombatantDetail` (`details/summary` under each `CombatantRow`, open for the active combatant) shows the slot ledger `<slot> <remaining>/<grant>`, pools, bound slots (only when the library reports any), conditions + pack `restricts`; reads `fight.runtime.pack`. No "down" labels (CX-D3, EG-2).
- **Offers** (DF-1 provenance via `offerEvents`): each open offer maps to the latest `trigger:fired` for its id. Declare/Step/offers disable while offers are open and after combat-over; the combat-over banner shows `combat:ended` `{winner, defeated}` verbatim; the log stays reviewable.
- A resumed fight (M09 `resume`) renders the same way; views read `fight.runtime`, which for a resumed fight is a fresh `Runtime` on the stored pack.
